# Анализ информационных систем, построенных по архитектуре веб-приложений

## 1. Понятие веб-архитектуры

Веб-приложение — информационная система, клиентская часть которой работает
в браузере (тонкий клиент), а вся бизнес-логика и хранение данных выполняются
на сервере. Классическая схема — трёхзвенная архитектура:

1. **Уровень представления** — браузер пользователя (HTML, CSS, JavaScript);
2. **Уровень приложений** — веб-сервер и серверные модули (IIS + ISAPI DLL,
   серверные сценарии, API);
3. **Уровень данных** — СУБД (MS SQL Server, PostgreSQL, MySQL и др.).

## 3. Оценка возможностей веб-архитектуры

**Преимущества, за которые веб-ИС вытесняют толстых клиентов:**

- доступ из любой точки с любого устройства, где есть браузер — не требуется
  установка клиентского ПО (нулевые затраты на развёртывание рабочих мест);
- централизованное обновление: новая версия разворачивается на сервере один раз;
- масштабируемость: нагрузку можно наращивать добавлением серверов приложений
  и балансировщиков;
- единая точка входа и централизованное разграничение доступа (роли, HTTPS);
- открытые REST API у большинства современных систем — лёгкая интеграция
  между собой и с мобильными приложениями;
- кроссплатформенность клиента: Windows, Linux, Android, iOS.

**Ограничения, которые нужно учитывать:**

- зависимость от качества канала связи и постоянной доступности сервера;
- нагрузка на сервер растёт с числом одновременных пользователей;
- требования к защите данных при передаче (обязателен HTTPS);
- часть сложных интерфейсов реализовать в браузере труднее, чем в нативном ПО.

## 4. Варианты использования веб-систем в компании

1. **Удалённая и распределённая работа** — сотрудники филиалов и надомники
   получают доступ к CRM и ЭДО без VPN-клиентов, только браузер.
2. **Работа с клиентами** — личные кабинеты, каталог услуг и оформление заказов
   (как реализовано в приложении «Турфирма» в составе этой работы).
3. **Внутренний информационный портал** — приказы, справочники, заявки,
   доска объявлений.
4. **Отчётность для руководства** — дашборды, доступные с любого устройства.
5. **Быстрый старт ИТ-инфраструктуры** — облачные веб-системы снимают с компании
   задачу содержания собственных серверов.

## 5. Вывод по выбору собственной разработки

Для учебного проекта выбрана связка **Delphi 10.2 + IIS + MS SQL Server**:
Delphi (технология WebBroker) позволяет в единой среде собрать серверный модуль
ISAPI с доступом к данным через ADO; IIS выполняет роль промышленного
веб-сервера с поддержкой HTTPS, пулов приложений и разграничения прав;
MS SQL Server обеспечивает надёжное хранение и целостность данных через
первичные и внешние ключи. Так получают типовой стек корпоративного веб-приложения,
работающего по трёхзвенной схеме «браузер → IIS → СУБД».
